# Stage 5 guidance: neutral selection and falsification

Select provisionally by causal fit, not by family label or breadth. Compare the supported
mechanism, assumptions, residual recurrence paths, compatibility risk, and before/after
testability. Words such as comprehensive, canonical, shared, and centralized carry no
positive weight without evidence.

A class-level or shared option is eligible only when at least two independent consumers or
failure paths have evidence references. Set `needs_ux_review` from the actual anticipated
surface, not from the family ID.

Apply the independence gate to broad/class-wide problem claims and newly introduced reusable
abstractions. Do not infer broad scope from the count of files, callers, or components touched
by one evidenced operation. Extending an existing shared helper, preserving its affected
callers, or changing ordering and protection across the same reachable path can remain
`single_path` work when those changes are causally necessary for that operation.

The independent falsification pass must inspect the evidence and repository, articulate the
strongest counterargument, and return `accept`, `reject`, or `insufficient_evidence`. It
may cite only exact runner-owned `mechanism_evidence_id` values for the selected
hypothesis/mechanism. Adapter, exception, observed-output, controlled, harness, static, and live
evidence are eligible. The server content-addresses the review against the selected option
and research receipt. A separately constructed complementary control is not mandatory when
typed exception, harness, static, or other mechanism evidence is paired with an actual
runner-replayed refuting counterexperiment already bound to the selected hypothesis. Do not
manufacture a control for shape compliance. Accepting a critical root-cause, interface, or
change-surface finding is forbidden. A bounded noncritical residual may be accepted or
mitigated only with its exact bound, evidence, rationale, and verification; it limits the
downstream outcome to `mitigated`. Critical gaps block selection. Neither pass may modify
the read-only workspace or invent
duration values absent from repository evidence.

Stage 5 owns semantic approval of the selected option's prospective outcome strategy. Review
whether the intended operation and success properties solve the source problem and cover the
established mechanism; reject marker-only, swallowed-error, diagnostic-only, or unbounded
success definitions. Review and content-address this strategy in every case. If Stage 3 retained
an optional executed outcome contract, treat it only as authenticated baseline/additional
evidence rather than as the exclusive post-change gate. A surface-only baseline contract does
not block a sufficient option strategy, and it cannot rescue a surface-only option strategy.
Stage-5 approval is design approval for Stage 6, not post-change proof; implementation and
outcome execution remain responsible for resolved/live-verified evidence.

Review `post_change_replay_mode` as part of that strategy. Prefer a clean runner-verified
fail-first command for the same source atoms. Reject an exit-zero assertion of the old symptom
when it is presented as an exact post-change replay or when the option proposes rewriting its
retained research asset. If no fail-first exists, `stage6_planned_unverified` is an honest,
nonblocking design boundary: Stage 6 must create a distinct future proof and later execution,
not pre-change research, determines whether it passes.

Treat an assertion about existing behavior, requirements, consumers, protection signals, or
reachable control surfaces as a factual claim that needs evidence. Treat a clearly labeled new
finite threshold, configurable bound/default, identity or alias rule, or interface extension as
prospective design. A prospective choice does not become a critical finding merely because the
old code did not already encode it. It may proceed when its compatibility tradeoff is bounded,
the source problem and established mechanism are covered, relevant safety constraints are
preserved, and Stage 6 can turn the proposed outcome checks into executable verification.
Reject the option when those conditions are absent; return to Stage 3 only when an indispensable
present-state fact remains unknown, not to have research choose the future policy.

This distinction does not excuse concrete gaps. Unsupported pre-build recovery claims,
unverified manual/shared consumers, unresolved active/protected/external-reference handling,
or verification that cannot distinguish the proposed behavior remain blocking findings.

Inspect the reachable end-to-end path and identify the earliest same-resource failure
boundary. An option that intervenes only after that boundary cannot recover the source
operation. Conversely, an evidenced earlier intervention is not broad scope merely because
implementing it requires sequencing across existing components.

Prefer safe useful throughput to unconditional aborts. A partial supporting-operation error
may be reported while the intended operation continues when verification establishes both a
safe postcondition and sufficient actual progress. Reject swallowed errors, assumed progress,
and continuation without safety proof, but also reject abort-on-any-error behavior that blocks
an otherwise verified safe success.

A prospective configurable value may be proposed as a default or tested bound. An observed
benchmark value or current default does not establish a universal supported maximum; that
stronger constraint requires a repository requirement or capacity basis.

For adapter evidence, distinguish the causal locator from its runner-attested implementation
touchpoints. A locator proves what was intervened on; selected touchpoint IDs prove which inspected
repository paths can implement the change. Missing or semantically disconnected production
touchpoints are a material change-surface gap, not permission to plan an `env:` or `fs:` path.

Structural and quality errors return to the exact role session that authored them. A valid
falsifier rejection returns bound substantive feedback to the original selector; it does not
discard the case. If no existing option can answer that critique, the selector requests option
revision and the original Stage 4 optioner session produces a revised zero-to-three option set.
Every revised selection receives a fresh independent falsifier review. Ancillary label failure
must use a neutral server-owned label and cannot invalidate an otherwise accepted selection.
