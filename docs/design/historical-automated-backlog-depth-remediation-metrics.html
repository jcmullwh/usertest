Measurement companion / evidence snapshot

Depth remediation is not yet qualified

The project has gained much stronger offline contracts, source-evidence accounting, and subscription-route proof. It has not yet demonstrated that a real shadow cycle can turn mined evidence into accepted causal research and a correct, code-grounded plan. This report keeps those results separate.

Snapshot: July 11, 2026 Branch: codex/backlog-depth-remediation Export: disabled Overall: not qualified

How to read these numbers

There is intentionally no blended project score. A deterministic test passing, a model returning output, a dossier passing causal verification, a shadow cycle qualifying, and an implemented case resolving its original problem are different claims. Combining them would make the current operational failures look better than they are.

Bottom line: offline contract suites are green, but live accepted-research throughput is zero in the measurements available here. No revised-pipeline case has completed the ticket-to-outcome lifecycle, so the current resolution rate is undefined, not 0% and not 100%.

Rates are denominator-bound

  • Percentages describe only the named sample.
  • The two Stage 3 attempts are retries for one case, not two independent cases.
  • The two shadows ran on different commits and do not form one stable streak.
  • Unknown and not measured are never silently converted to zero.

Evidence layers stay separate

  • Historical corpus: what the old process actually emitted.
  • Offline contract: deterministic behavior encoded in tests.
  • Live Stage 3: model output and evidence-gate behavior.
  • Live shadow: full export-disabled backlog cycles.
  • Outcome: implementation plus original-scenario and recurrence proof.

Scope is automated atom-derived work. IDEA and other externally originated items are excluded as sources of new automated cases.

What must happen before “working” is a supported claim

  1. Fix the aggregate support-connectivity and production-entrypoint false positive, then adversarially test it.
  2. Run the full project matrix and a new exact-revision, subscription-backed live Stage 3. A valid dossier must reach and pass evidence verification.
  3. Run two consecutive export-disabled shadows on one exact revision. Each must produce real cases, accepted research, code-grounded plans, and a stable case graph.
  4. Only after qualification, reconcile the stale generated queue while preserving IDEA/user and origin-unproven records.
  5. Regenerate, implement through usertest implement, replay original scenarios, record branch/commit/test/live evidence, and continue until the qualified backlog is actually complete.

Passing controls alone is insufficient. The decisive measurement is whether the system repeatedly finds real evidence, establishes a connected causal mechanism, produces a plan that closes that mechanism, and proves the original problem no longer occurs.
