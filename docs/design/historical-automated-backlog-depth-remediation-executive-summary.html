Executive assessment

The architecture has moved materially toward the objective, but the objective is not yet complete.

Code and offline tests now enforce lineage, causal research, code-grounded planning, and outcome proof. Live qualification has also proven that signed-in Codex research uses the host ChatGPT subscription rather than API-key billing. However, the latest controlled Stage 3 run correctly remained blocked because its model-authored dossier failed causal-output validation: the first attempt had two contract defects and the retry had one unresolved evidence reference. A separate adversarial review then found another structural issue: the verifier pressured each experiment to cover an entire multi-hop cause, which could encourage artificially shallow root-cause statements.

The work has therefore progressed beyond “add stricter prompts.” The system now has persistent case identity, evidence roles, same-cause reduction, runner-replayed research, an adversarial solution review, executable before/after outcome oracles, and lifecycle states that distinguish implementation from resolution. At the same time, several early controls were deliberately removed or redesigned when real runs showed that they optimized formal compliance rather than the user’s actual objective.

The overarching objectives

The governing objective is not to make pull requests impossible to scope incorrectly. Existing review and CI already cover ordinary PR scope. The remediation is aimed at five failure modes that occur earlier and later in the automated backlog lifecycle:

  1. Mine real, unactioned problems from all relevant automated evidence. Require every eligible source observation to receive an explicit disposition; do not let keyword selection, extraction caps, or partitioning silently erase important observations.
  2. Preserve causal identity and provenance. Research and implementation commentary about an existing case must not be re-mined as independent demand.
  3. Establish the mechanism, not merely the symptom. Research must inspect the exact revision, reproduce or deterministically trace the failure, consider counterevidence, and retain material unknowns.
  4. Select and plan a solution that closes the actual causal paths. “Canonical,” “shared,” or “comprehensive” language is not evidence; plans must name concrete code and executable proof.
  5. Prove what happened after implementation. A merged PR or moved ticket is not synonymous with the original problem being resolved.

Two operational constraints sit alongside those goals: the pipeline must have usable throughput rather than blocking everything, and automated Codex work must use the signed-in host ChatGPT subscription—not an API-key or per-token fallback.

How the system now works

The central architectural shift is from ticket-centric generation to a persistent evidence-and-case graph. Tickets are now downstream views of cases rather than the source of problem identity.

1. EvidenceEvery atom receives lineage, role, and a disposition.
2. Canonical caseMerge/split/same-cause decisions reduce work before research.
3. Research proofExact revision, experiments, symbols, controls, counterevidence, unknowns.
4. Solution + planNeutral causal coverage review and exact code/verification targets.
5. OutcomePre/post-merge original-scenario replay, live proof, recurrence, remaining risk.

Evidence and case identity

Stable case_id values persist across wording and ticket changes. Source, research, implementation, and verification evidence have different roles. Derived evidence updates its parent by default; only a runner-owned, typed operational failure can originate a new infrastructure case. Every high-severity atom must receive a durable disposition rather than silently falling outside a selected prompt slice.

Research as proof

Stage 3 now acquires the exact repository revision and can create research-only harnesses in an isolated workspace. The runner independently replays approved commands, checks artifacts and inspected symbols, binds hypotheses to evidence, and separates a blocked or insufficient investigation from an evidence-sufficient one. Runner-owned outcome oracles carry the demonstrated scenario forward rather than reducing research to prose.

Planning and adversarial review

Optioning is no longer required to manufacture direct/robust/comprehensive variants. Zero to three distinct mechanisms are allowed. A separate falsifier challenges causal coverage, unsupported breadth, residual failure paths, and the proposed positive outcome contract. Planning receives a clean checkout at the researched revision and must name exact files, symbols, data-flow changes, compatibility behavior, and executable checks.

Outcome and recurrence

The implementation loop distinguishes planned, implemented, tests-verified, original-scenario-verified, live-verified, mitigated, resolved, superseded, duplicate, and unverified states. The same proof used to establish the problem can run against the implementation before merge and the merged commit afterward. Same-class evidence updates or reopens the case rather than spawning a new prose-derived ticket.

Evolution of the remediation

July 9 — audit to implementation

Built persistent lineage and made relation decisions operational

The first implementation established stable cases, explicit atom dispositions, cumulative carry-forward, and merge/alias/split behavior. This directly addressed the historical feedback and deduplication failures.

July 10 — objective correction

Removed a PR-scope and anti-forgery ratchet

The initial hardening had accumulated line/blob/import/config/new-file ceremony. Those checks could make a PR formally constrained without proving that the problem was real or solved. They were demoted or removed. The remaining hard gates focus on mechanism coverage, problem-specific outcome proof, tested-head identity, and unresolved high/critical findings.

July 10 — mining recall

Replaced keyword-first mining with complete structured evidence passes

Extraction caps were removed, evidence was split into bounded but complete jobs, non-support decisions received independent review, and cross-partition anchors were preserved so supported evidence could not disappear from later relation work.

July 10 — research and outcomes

Connected causal research to executable before/after proof

Retained harnesses, static traces, causal interventions, positive outcome contracts, and clean-commit replays were added. This was the largest direct contribution to the root-cause objective: the plan’s claimed solution can now be checked against the exact researched scenario rather than only its own unit tests.

July 10–11 — first shadows

Rejected “all blocked” as a successful shadow

Early qualification could satisfy structural invariants while producing no useful research or plan. The gate was changed to require demonstrated positive depth when active cases exist, while still preserving honest case-specific blockers and not forcing an exhausted corpus to fabricate tickets.

July 11 — operational evidence

Recovered typed automation failures without re-mining generic agent errors

Sibling implementation history and pre-acquisition failures are now ingested through a bounded runner-owned projection. A live 185-record replay rejected nine generic AgentExecFailed envelopes and retained two typed disk-full occurrences.

July 11 — authentication redesign

Abandoned copied auth and login-only proof

Copying auth.json into a disposable Codex home could strand OAuth token refreshes outside the canonical host cache. Exact “Logged in using ChatGPT” output also did not prove that the model endpoint was canonical. The design now uses the host cache directly, blanks API/provider variables in the child only, forces canonical ChatGPT endpoints, and records pre/model/post route and auth receipts.

July 11 — host configuration cleanup

Replaced global byte-identity gating with targeted trust-residue cleanup

Installed Codex persists disposable workspace trust even with explicit overrides. Requiring the entire host config to remain unchanged would block legitimate user or concurrent Codex preference changes. Schema 3 now removes only the exact runner-added trust table under a writer-exclusive in-place handle and preserves all unrelated bytes.

July 11 — exact-commit live Stage 3

Research was substantive, but the proof contract still blocked it

Two subscription-backed Codex attempts ran for 549 and 685 seconds. Both exited zero and performed real repository investigation. Attempt 1 failed two dossier-contract fields; the full retry fixed those but invented an unsupported alternative and used a source atom in the wrong evidentiary direction. Those were the actual validation failures, and the block was correct. Follow-on adversarial inspection separately found that per-experiment full-symbol coverage encouraged shallow single-function hypotheses; its first aggregate replacement then failed semantic review because disconnected supports could be unioned into a false causal chain. A connected, symptom-rooted aggregate contract is required before shadow qualification resumes.

Bottom line

The project has evolved from a pipeline that generated polished tickets from partial, self-referential evidence into one with explicit contracts for preserving observations, building stable cases, establishing causal mechanisms, challenging solutions, and replaying original scenarios after implementation. Those contracts are materially stronger offline, but the live pipeline has not yet demonstrated an accepted research-to-outcome chain. The most important course corrections were removing PR-scope ceremony, rejecting all-blocked qualification, preserving the host subscription path, and requiring connected, symptom-rooted aggregate causal coverage.

The latest live failure is useful evidence rather than a setback to conceal: it proved the auth path, proved that real agents are doing substantive research, and exposed exactly where the proof contract still incentivizes the wrong shape of reasoning. Work should continue only after that defect is corrected and re-proven through real shadow cycles.
