What the code changes

  • Applies keep_local_count as an absolute budget for ordinary managed physical image identities, not raw tags.
  • Groups local and published aliases by physical identity.
  • Preserves configured, current, running, and otherwise protected identities across aliases.
  • Runs cleanup before the batch scratch build and before direct resolver pull/build storage writes.
  • Keeps prewrite, post-resolution, and manual cleanup results distinct.
  • Reports actual post-cleanup inventory and blockers such as external tags or container references.

Why this is not merely a surface patch

The visible symptom was disk exhaustion. Simply emitting a warning, deleting more old tags, or adding another cleanup call after a build would not fix the failure. The final change addresses three causal dimensions established by research and optioning:

  1. Eligibility: fresh age must not override the absolute ordinary-identity budget.
  2. Timing: capacity must be reclaimed before operations that need Docker storage.
  3. Identity/safety: multiple tags for one image must not inflate accounting, and protected or referenced identities must remain protected.

What remains unproven

  • Actual reclamation against an isolated Docker daemon.
  • Successful recovery of both constrained storage-write arms.
  • No over-deletion of external/current/container-referenced identities in a live daemon.
  • Recurrence-free behavior in a later automated backlog cycle.
  • A durable OutcomeRecord linked to the ticket, plan revision, branch, and PR.
